# eladmin endpoint census

A dependency-free, single-file Java 21 tool that statically scans the controller
sources in this checkout and produces a deterministic census of all method-level
HTTP endpoints. It never starts the application, never uses the network, and
never writes to anything except the two output files you name on the command
line.

## Files

- `EndpointCensus.java` - the generator and verifier (one file, JDK 21, no
  third-party dependencies, nothing added to any `pom.xml`).
- `endpoint-census.txt` - the committed census artifact (UTF-8, LF line endings).
- `endpoint-census.txt.sha256` - SHA-256 of the canonical census body, as 64
  lowercase hex characters followed by a single LF. The checksum file content is
  byte-identical across runs.
- `.gitattributes` - pins LF line endings for everything in this directory so
  the artifact bytes stay stable on any OS and any `core.autocrlf` setting.

## Usage

From the repository root:

```
java tools/endpoint-census/EndpointCensus.java <repoRoot> <outputFile> [generate|verify]
```

- `generate` (default) scans the sources and writes `<outputFile>` plus the
  companion checksum file `<outputFile>.sha256`.
- `verify` re-scans the sources, rebuilds the census in memory, and compares it
  byte-for-byte against the stored artifact and its checksum file. Exit code 0
  means no drift; nonzero means drift, a count mismatch, a missing artifact, or
  a checksum mismatch.

To re-verify the committed artifact:

```
java tools/endpoint-census/EndpointCensus.java . tools/endpoint-census/endpoint-census.txt verify
```

## What the tool enforces

- The scan must find exactly 139 endpoint records: 132 `direct_verb`,
  6 `anonymous_composed`, 1 `bare_request_mapping`.
- No duplicate records (full-record uniqueness).
- In verify mode, stored bytes must equal regenerated bytes, and the stored
  checksum file must equal the regenerated checksum.
- Any discrepancy is a hard failure with a nonzero exit code; entries are never
  guessed, padded, or hand-edited into existence.

## Census format

Seven pipe-separated columns per row, sorted by route, then HTTP method, then
controller simple name, then handler method, then source path, then source line:

| Column | Meaning |
| --- | --- |
| `mapping_kind` | `direct_verb` for `@GetMapping`/`@PostMapping`/`@PutMapping`/`@DeleteMapping`/`@PatchMapping`; `anonymous_composed` for the `@Anonymous(Get|Post|Put|Delete|Patch)Mapping` composed annotations in `eladmin-common/src/main/java/me/zhengjie/annotation/rest/`; `bare_request_mapping` for a method-level `@RequestMapping` without an HTTP method constraint |
| `http_method` | single upper-case verb, or the explicit marker `UNKNOWN` when the mapping does not constrain the method (currently exactly one row: the Alipay asynchronous notify callback) |
| `route` | normalized route (see below) |
| `controller_simple` | simple class name of the `@RestController` |
| `controller_fqn` | fully qualified class name |
| `handler_method` | handler method name |
| `source_location` | repository-relative path and 1-based line number of the mapping annotation |

## Route normalization rules

1. The route combines the class-level `@RequestMapping` prefix with the
   method-level path the way Spring's `PatternsRequestCondition.combine`
   does: an empty fragment yields the other fragment; the join point
   carries exactly one slash; a missing slash on both sides is inserted
   (class `AppRun` carries no prefix; combining with an empty prefix is
   a no-op).
2. The empty route becomes `/` (the `AppRun` index endpoint).
3. A leading `/` is enforced.
4. Duplicate slashes are collapsed (`//` becomes `/` repeatedly).
5. Historically the tool concatenated without inserting the join slash,
   which mis-recorded `/api/generatorsync` and `/api/userscenter` for
   routes Spring actually serves as `/api/generator/sync` and
   `/api/users/center` (`GeneratorController` declares
   `@PostMapping(value = "sync")` under the `/api/generator` prefix and
   `UserController` declares `@PutMapping(value = "center")` under
   `/api/users`). The baseline and checksum were regenerated together
   with that fix.
6. `EmailController` carries the class-level prefix `api/email` with no
   leading slash and an empty method path, which normalizes to
   `/api/email`.

## Method extraction rules

- A `@RequestMapping` that declares no `method = RequestMethod.*` attribute
  produces one row with `http_method = UNKNOWN` and kind `bare_request_mapping`.
- A `@RequestMapping` with `method = RequestMethod.X` is classified as
  `direct_verb` with verb `X` (one row per RequestMethod constant listed).
- The `@Anonymous*Mapping` composed annotations are classified as
  `anonymous_composed` with the verb encoded in the annotation name.
- Comments are masked before scanning; strings, text blocks, and char literals
  are handled so braces, quotes, and comment-like sequences inside them cannot
  confuse the parser.

## Regenerating after intentional endpoint changes

Only regenerate when a code change intentionally adds, removes, or moves
endpoints, then review the diff row by row:

```
java tools/endpoint-census/EndpointCensus.java . tools/endpoint-census/endpoint-census.txt generate
git diff -- tools/endpoint-census/
```

If the total stops being 139 (or the 132/6/1 kind breakdown shifts), the tool
fails loudly instead of writing a drifted artifact; update the expected counts
in `EndpointCensus.java` deliberately, together with a review of the endpoint
change that caused the shift.

## Provenance

The census and its anchors (139 total; 6 anonymous endpoints; the single
`/api/aliPay/notify` `UNKNOWN` row) are cross-checked against the baseline
endpoint inventory recorded at the start of the migration, which records
139 method-level endpoints across 26 `@RestController` classes.
